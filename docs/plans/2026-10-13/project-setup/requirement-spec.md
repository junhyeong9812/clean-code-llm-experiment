## 1. 목표·대상 (필수)

- **대상:** 새 저장소 `/home/jun/project/clean-code-llm-experiment`
- **이번 작업 범위(셋업):**
  1. git 저장소. main 초기 커밋(README·.gitignore)만 두고, 셋업은 `feat/project-setup` 브랜치에서 한다.
  2. Gradle(Kotlin DSL) 멀티 모듈 뼈대
     - `god/`: 갓 클래스 구현
     - `layered/`: `api · service · domain · infra` 구현
     - `behavior-tests/`: 두 구현이 함께 통과해야 하는 HTTP 수준 행위 테스트 소스. 두 모듈의 test 소스로 공유한다.
     - 각 모듈은 Spring Boot 앱이고 `/actuator/health` 수준의 스모크 테스트를 둔다. 스모크는 도커 PostgreSQL에 붙어 통과해야 한다.
  2-1. `docker/compose.yml`: PostgreSQL 17(로컬 이미지), 포트는 127.0.0.1에만 연다. 접속 정보는 환경변수(`DB_URL`·`DB_USER`·`DB_PASSWORD`)로 주고 기본값은 로컬 개발용.
  3. README: 배경(graph-nav-experiment 결론 + 후기), 질문·가설, 설계(갓 클래스 → 레이어드 분리), 단계 계획
  4. GitHub 공개 저장소 생성, main과 셋업 브랜치 푸시
  5. graph-nav-experiment README 후기에 새 저장소 링크를 넣고 main 병합·푸시
- **끝의 정의:** 오프라인 `./gradlew build`가 두 모듈 모두 green이다. 원격 저장소가 공개이고 README에 계획이 있다.
- **이번 범위 밖(다음 작업들):** 결제 절차·포인트 규칙 정의와 DB 설계(다음 작업), 데이터 생성기(CSV)·적재·시드 이미지(스키마가 절차 정의에 달려 있음), 결제 절차 정의서, 행위 테스트 작성, 갓 클래스 구현(1만 줄+), 레이어드 분리, 과제·판정·러너, 본 실행. 각각 새 작업 폴더 spec부터 한다.

## 2. 경계·불변식 (필수)

- **버전 고정(로컬 캐시에 있는 조합, 오프라인 빌드 가능):** JDK 21(21.0.5-tem), Kotlin 2.2.20, Spring Boot 3.5.5, Gradle wrapper 8.14.4. 저장소는 JPA + PostgreSQL 17(도커, 로컬 이미지 `postgres:17`). 실험 사본은 네트워크 없이 빌드돼야 하기 때문이다(DB는 루프백 접속이라 외부 네트워크 불필요).
- **두 모듈의 공개 계약 동일:** 같은 HTTP API·같은 행위 테스트를 공유한다. 셋업 단계에서는 계약 자리만 만든다.
- **실험 공정성:** 저장소에는 실험 조건(어느 쪽이 좋을 것이라는 가설·판정 자료)을 에이전트 작업 사본에 노출하지 않는 구조를 둔다. 예: `docs/`·`oracle/`은 사본 제외 대상. 러너 단계에서 강제한다.
- 커밋·발행 본문에 AI attribution을 넣지 않는다.

- **데이터 계획(다음 작업의 설계 입력, 이번엔 README에 기록만):**
  - 원본은 CSV, 생성기로 재현한다. CSV·DB 덤프는 git에 넣지 않는다(크기). 생성기·시드·행 수·체크섬만 커밋한다.
  - 실행마다 컨테이너: 시드 데이터를 적재한 이미지를 한 번 만들고(PGDATA를 볼륨 밖 경로로 두고 커밋), 실행마다 그 이미지로 컨테이너를 띄운다. 매번 CSV를 다시 적재하지 않는다.
  - 데이터 검증: 적재 후 행 수·합계·고아 행 검사. 과제 판정에도 DB 상태(레코드 수준) 검사를 넣는다.
  - 디스크: 여유 53GB(89% 사용). 시드 이미지 1개 + 실행별 쓰기분만 쓰도록 한다. 실행 전 여유 검사를 러너에 넣는다(앞 실험의 디스크 사고 교훈).
