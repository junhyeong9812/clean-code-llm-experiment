## 1. 목표·대상 (필수)

`docs/adr/0005-tasks-judging-runner.md`(새 ADR)를 써서 사용자 합의를 받는다. ADR은 이후 구현 작업(러너·과제·oracle)이 바로 착수할 수 있을 만큼 구체적이어야 한다: 실험 조건, 과제 후보 8개(유형별 2)와 각 과제의 구조별 주입 지점·판정, 러너 동작, 지표·통계, 파일럿 게이트, 타당성 위협.

## 2. 경계·불변식 (필수)

- **공정성:** 두 구조는 같은 과제 문장(TASK.md)·같은 공개 테스트·같은 숨은 테스트(HTTP·DB 수준, 구조 중립)를 받는다. 구조마다 다른 것은 코드와 oracle의 정답 패치·관련 심볼 목록뿐이다.
- **누출 금지:** 과제 문장·공개 테스트에 원인 위치(클래스·함수·파일 이름)를 쓰지 않는다. 에이전트 사본에서 oracle·숨은 테스트·실험 저장소에 접근할 수 없다.
- **판정 결정성:** 숨은 테스트는 정답 패치로 N회 반복해 전부 통과하고, 원본(주입 상태)에서 실패해야 채택한다. 요구하는 경로가 두 구조 모두에서 실제 호출되는지 확인한다(앞 실험 과제 05 교훈).
- **측정 정직성:** 토큰은 `result.modelUsage` 합계, 무효 실행(감사 위반·결과 없음(러너가 시간 상한으로 끝낸 실행은 제외 — censored, ADR-0005 §5.3)·인프라 오류·사용량 한도)은 지표에서 빼고 따로 센다 — 무음 제외 금지. *(리뷰로 보정)*
- 이 작업은 문서만 바꾼다(앱·테스트·도구 무변경).

## 5. 검증 방법 (필수)

- 설계 선검증(Opus 워커): ADR이 정한 동작 불변식(공정성·누출 금지·판정 결정성·측정 정직성)이 과제 후보마다 성립 가능한지 — 특히 주입 지점이 두 구조에 같은 의미로 존재하는지, 숨은 테스트를 HTTP 수준으로 쓸 수 있는지를 실코드(file:line)로 확인.
- 듀얼 1패스(Opus ∥ codex → 종합 → codex 감사 → post-fix 재점검). 렌즈: 공정성(구조 편향), 측정 타당성(지표가 가설을 재나), 판정 결함 가능성, 앞 실험 교훈 반영, 구현 가능성.

## 6. stakes (필수)

- 판정: **높음** — 실험 결론을 좌우하는 장기 설계 결정(되돌리면 실행 비용 전체가 무효). 산출물이 설계 문서라 리뷰 상한은 설계 선검증 + 듀얼 1패스.
