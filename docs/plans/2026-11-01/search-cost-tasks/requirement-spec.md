## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "②번으로 진행해줘 결국 심플하게 보면 결국 목적에 맞는 코드를 얼마나 더 빠르게 찾을 수 있는가네?" — 2차 결론 근거 문서 §5의 후보 ②(과제 난이도 수단 재검토 — 검색 단서).
- 인터뷰 2026-11-01:
  - 과제 유형: 증상만 주는 버그 · 용어 불일치 · 흩어진 규칙 변경 · 영향 범위 확인형 — **4개 모두, 유형마다 과제 1개(4개)**.
  - 주 지표: **첫 정답 편집까지 턴**(총 턴·성공률은 보조).
  - 코드베이스: **현재 확장본**(god 5,678 · layered 9,970줄).
  - 진행: **ADR-0008 사전 등록 → 과제 4개 → 파일럿**(파일럿 실행 전 사용자 재확인).
  - 게이트: **찾기 턴 기준 새로 등록**(예: 구조별 첫 정답 편집 턴 중앙값 ≥ 기준선 × k + 성공 ≥ 1, 기준선은 지난 12실행 원자료 재집계 — 정확한 수치는 ADR 초안에서 [제안] 후 합의).
  - stakes: **중간, 단계별 듀얼 1패스**(+ 과제 재채택 판별력 검사).

## 1. 목표·대상 (필수)

1. **ADR-0008**(채택): 가설("찾기 비용이 있는 과제에서 구조가 첫 정답 편집 턴에 영향을 준다"), 과제 유형 4개의 정의와 '키워드가 고칠 곳으로 바로 닿지 않음'의 판정 기준, 주 지표('첫 정답 편집' 정의 — 오라클 고칠 곳과 겹치는 첫 편집 도구 호출), 기준선 재집계, 파일럿 게이트·결론 행(§6.3 형식), 위협. **결과를 보기 전 사전 등록**이고 사후 선택임을 명시.
2. **과제 4개**(T3~T6 가칭): 기존 T1·C2와 같은 틀(TASK.md·TYPE·checks / oracle: fix·inject·naive·hidden·symbols·design) — 두 구조에서 정답 success, naive 숨은 실패, 두 구조 숨은 실패 수 대칭.
3. **지표 추출**: raw 이벤트에서 '첫 정답 편집까지 턴'을 뽑는 집계(지난 12실행 기준선 포함).
   - (2026-11-01 리뷰 R19) 기준선은 현재 과제 정의 8실행(2회차·파일럿 A)으로 한다 — 1회차는 과제 정의가 달라 같은 범위로 판정할 수 없다(ADR-0008 §5.5). ADR 채택 때 사용자 확인.
4. 끝 = ADR 채택 + 과제 4개 재채택 통과 + 기준선 집계 완료 + **파일럿 실행 직전에서 멈추고 사용자 확인**.

## 2. 경계·불변식 (필수)

- 사전 등록: 게이트·결론 문장·지표 정의는 파일럿 결과를 보기 전에 ADR-0008에 고정하고, 결과를 본 뒤 바꾸지 않는다.
- 두 구조 공정성: 과제 문구는 두 구조에 같은 문장(구조별 식별자·파일명 금지) · 구조별 키워드 적중 수 점검(낱말 대칭 — 비대칭이면 기록·정리) · 숨은 실패 수 대칭.
- '찾기 비용' 조건: 과제 문구의 낱말로 grep 했을 때 고칠 곳이 바로 나오지 않음을 두 구조에서 실측해 기록(ADR 판정 기준대로).
- 앱 동작 불변: 과제 주입(inject)은 과제 브랜치 상태에서만 — 기준 앱 소스·계약 테스트(contract1~3)·equiv는 바꾸지 않는다. 앱 소스 변경이 필요해지면 멈추고 보고.
- 기존 T1·C2·결과 디렉터리(`results*`)는 건드리지 않는다.

## 5. 검증 방법 (필수)

- ADR-0008: 설계 선검증(새 동작 불변식 = 지표 정의·게이트) + 듀얼 1패스(Opus ∥ codex) → 종합 → 재점검 1회 → 사용자 채택.
- 과제: T1·C2와 같은 재채택 — 고정 SHA에서 정답(fix) 전 단계 success, naive 전부 숨은 실패, 숨은 실패 수 두 구조 대칭, 판정 재현 2회. grep 실측 기록. 과제 묶음 듀얼 1패스 + 재점검.
- 지표 추출: 지난 12실행에 적용해 손으로 센 2~3개와 대조 · 단위 테스트(경계: 편집 없음·실패한 편집·고칠 곳 밖 편집).

## 6. stakes (필수)
