## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "계속 진행해줘" → NEXT N1(1·2단계 open question 정리 — 계약 공백, 사용자 판단)
- Q/A:
  - 산출물 범위 → **결정만 기록**. 항목마다 '현행 확정' 또는 '변경'을 ADR에 적고, 변경은 NEXT에 별도 구현 작업으로 올린다. 앱 코드는 바꾸지 않는다.

  - 배치 대상 1건이 PG_UNAVAILABLE 외 예외로 실패 → **건별 격리로 변경**(그 대상만 롤백·로그, 다음 대상 계속)
  - 늦게 승인된 주문의 발송 기한(승인 시점에 이미 `paid_at + 3일` 경과 가능) → **ADR 문자대로 유지**(확정)
  - 현행 확정(ADR 명시): 로그·시각 세부 3건(PAYING인데 APPROVE 행이 있으면 로그 없이 건너뜀 · 요청 시각을 잠금 전에 읽음 · 교차 구매자 같은 키 경합마다 Hibernate ERROR 로그) · 구매 경고 계수 경계(ADR 원문 엄격 >) · PG 취소 성공 뒤 커밋 예외(§7.2 계약 밖과 같은 종류)·검수 reason 공백 집합 · 포인트 묶음 전체 적재
  - 500k 규모 → **NEXT에 별도 측정 작업**(이번엔 결정하지 않음)
  - stakes → **높음** · 진행 → **auto** · 병합 → **ff 병합 후 main·브랜치 푸시**(승인 창)

## 1. 목표·대상 (필수)

ADR-0003·0004에 "확정 동작" 노트를 추가해, NEXT N1의 open question 각각이 **현행 확정 / 변경 예정 / 별도 측정** 중 하나로 닫힌 상태가 된다. 완료 조건:

- 확정 항목: ADR 해당 절에 동작 문장 + "사용자 결정 2026-10-24"가 있고, 그 문장이 god·layered 현재 코드와 맞는다(file:line로 확인).
- 변경 항목 2건(오류 문구 고정, 배치 건별 격리): ADR에 **새 계약 문장 + "구현 전 — NEXT 참조"** 표시, NEXT에 구현 작업 후보(영향 범위: god·layered·행동 테스트·equiv)로 올림.
- 500k 규모: NEXT에 측정 작업 후보로 분리(500k 이미지 재빌드 포함).
- NEXT N1 제거, layered '구조 차이' 항목은 과제 러너 분석 메모로 옮김.

## 2. 경계·불변식 (필수)

- **문서만 바꾼다:** 앱·테스트·도구·스키마 무변경. 변경 결정은 ADR에 "구현 전"으로 표시해, 현재 코드와 ADR 문장이 다르다는 사실이 숨지 않게 한다.
- **확정 문장은 현재 코드와 일치해야 한다:** 코드와 다른 문장을 '확정'으로 적지 않는다(god·layered 양쪽 확인).
- 구매 경고 경계: ADR §7의 `[기본값 — 생성기와 같은 해석]` 표시는 같은 시각 연속 경고에서 생성기(`seedgen.py:522-525`, 제한 시 목록 초기화 후 같은 시각 경고도 셈)와 다르다 — 이 차이를 문장으로 남긴다(시드·verify 영향 없음은 god 1단계 M-1 판정 승계).
