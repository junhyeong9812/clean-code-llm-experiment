## 1. 목표·대상 (필수)

다음 네 가지를 만들고, ADR-0005 §7의 3 파일럿 게이트로 판정해 끝낸다.

1. **판정 단계(ADR §4.1).** 실행 뒤 컨테이너에서 다음 순서로 돈다. 보호 파일 sha 검사 → 앱 bootJar → 공개 테스트 · 숨은 테스트 · 회귀(`contractTest` + `contract2Test` − regression-exclude, `verify.sql` − verify-exclude). 각 단계는 새 1k DB + 새 앱 + 가짜 PG에서 돈다. 결과는 success와 보조 지표로 `runs.jsonl`에 남긴다.
2. **공개 테스트 모듈.** 작업 사본의 Kotlin JUnit 모듈과 최소 지원 코드(HTTP·DB·시계·트리거 도우미만 — 규칙 상수·기대 금액·키 형식 없음). `test.sh`가 앱을 띄우고 이 모듈을 돌린다.
3. **과제 T1·C2(ADR §3.2).** 공개(`TASK.md`·`TYPE`·`test.sh`·공개 테스트)와 비공개(`design.md`·`fix/inject` 패치(두 구조)·숨은 테스트·`symbols`·`regression-exclude`·`verify-exclude`). 규칙 서술 주석은 두 구조 모두 지운다(ADR §3.1).
4. **러너 소수정(ADR 개정 1 '변경 예정').** `sed -n` 범위 읽기에 Read 규칙을 적용한다. usage_limit 근거를 stderr와 result·system 이벤트로 한정한다. 예열 주석 수치를 실측으로 고친다. ADR §5.2·§6.4 해당 문단도 함께 갱신한다.

그다음 파일럿(T1·C2 × 2구조 × Sonnet × 1)을 돌려 게이트를 판정한다.

## 2. 경계·불변식 (필수)

- **구조 중립:** 두 구조는 같은 `TASK.md`·공개 테스트·숨은 테스트를 받는다. 구조마다 다른 것은 앱 코드, `fix`·`inject` 패치, `symbols`뿐이다.
- **과제 채택 조건(ADR §3.1, 실측):**
  - 주입 상태(T1)나 기준 상태(C2)에서 숨은 테스트가 실패한다.
  - 정답 패치를 적용하면 두 구조 각각에서 숨은·공개 테스트가 **5회 반복 전부 통과**한다.
  - `design.md`에 적은 순진한 오답마다 숨은 테스트가 실패한다.
  - 정답 패치 + regression-exclude로 회귀가 통과하고 verify 위반은 0이다.
  - 숨은 테스트가 요구하는 경로가 두 구조에서 실제로 호출된다.
- **누출 금지:**
  - `TASK.md`·공개 테스트·지원 코드에 원인 위치(파일·클래스·함수)나 규칙 상수·기대값 형식을 쓰지 않는다.
  - oracle·숨은 테스트·behavior-tests 소스는 에이전트 사본에 없다. 판정 컨테이너에만 있고, 그 컨테이너는 에이전트 실행이 끝난 뒤에 뜬다.
- **판정 정직성:**
  - success = 빌드 ∧ 공개 ∧ 숨은 ∧ 변조 없음 ∧ 회귀.
  - 보조로 "회귀를 뺀 성공"을 함께 남긴다.
  - 컴파일 실패·테스트 실패·인프라 오류를 구분한다. 회귀가 인프라 오류로 판정 불가면 그 실행은 무효(재판정)다.
  - 판정을 건너뛴 실행은 행에 `judged=false`와 사유를 남긴다.
- **판정 컨테이너도 격리한다:** 실행 네트워크와 같은 방식(`--internal`, 외부 접속 없음)으로 띄운다. 에이전트가 쓴 코드는 호스트가 아니라 컨테이너에서 빌드·실행한다.
- **러너 불변식 유지:** runner-smoke 명세 §2 전부(마운트·로그인 파일·측정 정직성·정리·하네스 미로드·재현성)를 그대로 지킨다.
- **사전 기준·과제 정의 불변:** ADR §1·§3.2를 바꾸지 않는다. 파일럿을 보고 과제를 바꾸면 변경 이력을 남기고, 파일럿 실행은 본 표본에 넣지 않는다(ADR §7).

## 4. 금지영역 (필수)

- `god/`·`layered/` 원본 소스 수정 금지. 주입·정답은 패치 파일로만 둔다.
- `behavior-tests/` 소스 수정 금지. 회귀는 읽기 사본을 판정 컨테이너에서 돌린다.
- `tools/` 수정 금지. `docker/`·ADR-0001~0004 수정 금지.
- ADR-0005는 §5.2·§6.4 '변경 예정' 문단 갱신만 허용한다.
- 파일럿 4회 밖의 에이전트 실행은 하지 않는다. 실패한 실행을 다시 돌려야 하면 다시 묻는다. 과제 검증(채택 조건)은 에이전트 없이 패치로만 한다.
- study-note 쓰기 금지. main 직접 작업 금지. push는 사용자 확인 후.

## 5. 검증 방법 (필수)

- **과제 채택 조건 실측:** §2의 다섯 가지를 판정 단계로 실제 실행해 확인한다. 정답 5회, 주입·오답 각 1회.
- **판정 단계 테스트:**
  - 단위 테스트: 보호 파일 sha, 결과 파싱(JUnit XML → 실패 테스트 목록), 단계 구분(컴파일·테스트·인프라).
  - 무료 스모크: 정답 패치와 오답 패치를 사본에 적용한 뒤 에이전트 없이 판정만 돌린다.
- **러너 소수정:** fix verification 테스트와 기존 162개 통과.
- **blind 테스트 워커:** 명세와 ADR만 보고 판정 단계 계약을 테스트한다(구현 diff는 열람하지 않음).
- **파일럿:** ADR §7의 3 게이트. 4실행 모두 valid ∧ 지표 전부 파싱 ∧ 하나 이상 성공 ∧ 구조마다 턴 중앙값 10 이상. 비용·시간·censored를 보고한다.
- **리뷰:** 듀얼 리뷰 루프(≤3). 렌즈에 "이 과제가 어느 구조에 유리한가"(ADR §9 위협 4)를 넣는다.

## 8. load-bearing 가정

1. 판정 컨테이너에서 behavior-tests(Kotlin, 오프라인 RO 캐시)가 에이전트 사본의 앱 jar를 대상으로 돈다. 회귀 1회 시간은 병렬 3 운용이 가능한 수준(수 분)이다. 판정 골격 직후, 정답 패치 없는 기준 사본으로 회귀를 실측한다.
2. T1의 숨은 테스트가 자연 흐름으로 만료·생성 순서를 엇갈리게 만들 수 있다(ADR §3.2 — 확정 사이 시계 이동). 주입 상태에서는 결정적으로 실패하고 정답에서는 통과한다. D12(이월 항목)도 함께 실측한다.
