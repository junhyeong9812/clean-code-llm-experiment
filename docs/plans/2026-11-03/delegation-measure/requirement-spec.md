# 요구사항 명세서 — ADR-0009 탐색 위임 측정

> 작성일: 2026-11-03 · 작업 폴더: `docs/plans/2026-11-03/delegation-measure/` · 브랜치 `delegation-measure`(`search-cost-tasks` `0628fff`에서 — fce·과제 S1~S4 포함, main 미병합)
> 산출물 유형: **혼합** — 설계(ADR-0009) + 실행물(러너 위임 방식·새 과제 3개) + 실험 실행. 진행은 단계마다 사용자 확인(아래 §1).

## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "필요한 파일을 가져와서 정리하는건 히카루나 소넷한테 시키고 정말 중요한 해당 재료를 바탕으로 의사결정 하도록 … 더 토큰을 적게 사용할 수 있지않을까?" → "a가 최선인데 … 하네스를 바꿀 필요가 없다는게 정론이 되어버리는거야?" → "우선 바로 적용하지말고 우리 실험 마무리하고 한번에 하네스를 바꾸는게 맞지않아?" → "ADR-0009 인터뷰 시작해줘" → "현재 pc에서 부하를 주는 테스트를 진행중이라 영향이 가지않게 최대 세션수를 좀 제한해서 실험을 진행해줬으면 좋겠어."
- 인터뷰 결정(2026-11-02~03): 메인 Opus · 방식 4개 = 직접 / +Haiku explorer / +Sonnet explorer / +Opus explorer(대조) · god·layered 둘 다 · 과제 = S1~S4 + 탐색량 큰 새 과제 3개(교차 기능 변경·원인 추적 버그·조사·보고 후 수정, 유형별 1개, ADR-0008 수준 채택) · 본 실행 3회·상한 $100 · 위임 지시 = 하네스식 규칙 · 주 지표 = 명목 총비용 비(위임÷직접) + 성공 비열등 · 판정 표 제안값 · 파일럿 = 동작·비용 확인 · stakes 중간.

## 1. 목표·대상 (필수)

질문: **Opus 메인이 탐색을 싼 모델 워커에 맡기면, 성공을 잃지 않고 총비용이 주는가.** 단계(각 단계 끝에 사용자 확인):
1. **ADR-0009** — 방식·과제·지표·결과별 할 일 표·파일럿 게이트를 결과 보기 전에 등록(채택 = 사용자 합의).
2. **러너 위임 방식** — 작업 사본에 `.claude/agents/explorer.md`(model 지정) 주입 + 방식별 프롬프트 접미(하네스식 위임 규칙), runs.jsonl에 방식·explorer 호출 수·모델별 비용 기록. 단위 테스트.
3. **새 과제 3개** — fix·alt·naive 패치, 숨은 테스트, 두 구조 채택 행렬 통과.
4. **파일럿**(방식 4 × 구조 2 × 새 과제 3 = 24실행) → 게이트 → 사용자 확인 → **본 실행**(4 × 2 × 7과제 × 3회 = 168실행) → 결과별 할 일 표 적용 → 결론 문서(4차 결론).
- 끝 = 결론 문장 + 하네스 개정 입력(claude-code-harness 보류 브랜치 재개 조건).

## 2. 경계·불변식 (필수)

- **결과별 할 일 표·문턱·지표 정의는 파일럿 실행 전에 ADR-0009로 고정** — 결과 본 뒤 바꾸지 않는다(바꾸면 사후 변경 표시).
  - 비용비 r = median(위임) ÷ median(직접), 과제·구조별 → 기하평균. **< 0.8 · 비열등 → 탐색 워커 기본 모델 변경 / 0.8~1.25 → 탐색량 큰 과제에서만 < 0.8이면 '큰 탐색에만 위임', 아니면 현행 유지 / > 1.25 또는 열등 → 현행 유지(근거 기록).** 95% 부트스트랩 구간이 문턱을 포함하면 '불확실'.
  - 비열등 = 위임 방식 성공 수가 직접보다 (과제·구조 합계) 1건 넘게 적지 않음.
- 앱 소스·계약 테스트·equiv·시드 불변. 기존 과제 S1~S4 판정 자산 불변(재사용만). 직접 방식 = 현행 러너 동작과 같아야 한다(회귀 테스트).
- 위임은 지시(하네스식)이지 강제가 아니다 — explorer 호출 수를 기록하고 미호출 실행도 표본에 둔다.
- **PC 부하 제한(사용자 요청):** 러너 `--parallel 1`(에이전트 컨테이너 동시 1개) · 채택 행렬 판정도 동시 1레인 · 동시 서브에이전트(워커) ≤ 2 · codex 리뷰는 한 번에 1개 · 실행 전 `free` 기록, 가용 메모리 < 12GB면 대기. 사용자가 부하 테스트를 끝냈다고 하면 완화를 다시 묻는다.
- 예산: 본 실행 상한 $100, 파일럿 뒤 Opus 실측으로 재추정해 초과 예상이면 사용자 결정.

## 3. 기준소스 (필수)

ADR-0005(러너·판정·지표) · ADR-0008(과제 채택 수준·fce) · 1~3차 결론 · `experiment/runner/{runner.py,events.py,judge.py,fce.py}` · Claude Code 서브에이전트 정의 형식(`.claude/agents/*.md` frontmatter `model`) — 착수 때 실제 CLI(컨테이너 2.1.308)에서 스모크로 확인.

## 4. 금지영역 (필수)

앱(god·layered) 소스·계약 테스트·시드·equiv · 기존 결과 폴더(results*) · ADR-0005~0008 사전 기준 · 하네스 repo(보류 브랜치 — 이 결론 뒤 별도) · study-note 쓰기 · push·병합(사용자 확인) · 본 실행 착수(파일럿 게이트 후 사용자 확인).

## 5. 검증 방법 (필수)

- ADR-0009: 듀얼 1패스 + 재점검(설계 문서 분기).
- 러너: 단위 테스트(방식별 argv·주입 파일·기록 필드, 직접 방식 회귀 = 기존 테스트 전부) + 1실행 스모크(Haiku explorer 실제 호출·by_model 분리 확인) + 듀얼 1패스.
- 새 과제: 채택 행렬(fix·alt 전 단계 통과, naive·none 숨은 실패, 두 구조) + 듀얼 1패스.
- 파일럿·본 실행: 수치 원자료 재계산, 결론 문서 듀얼 1패스.

## 6. stakes (필수)

- **중간** — 실험 장치·과제·보고(ADR-0008과 같음). 하네스 정책 변경은 이 결론 뒤 별도 작업(높음).

## 7. 자율성

- [x] auto(단계 경계마다 사용자 확인 — §1)

## 8. load-bearing 가정

1. 헤드리스 `claude -p`(CLI 2.1.308, bypassPermissions)가 작업 사본의 `.claude/agents/explorer.md`를 읽어 frontmatter `model`로 서브에이전트를 띄우고, 그 토큰이 `modelUsage`에 모델별로 잡힌다 — **러너 착수 직후 1실행 스모크로 실증**.
2. 하네스식 위임 지시만으로 Opus가 탐색량 큰 과제의 절반 이상에서 explorer를 호출한다 — 파일럿 게이트로 확인(미달 = 사용자 결정).
