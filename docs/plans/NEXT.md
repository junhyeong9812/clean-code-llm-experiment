## 다음 작업 후보 (우선순위순)

### N1. 갓 클래스 구현 1단계 — 우선순위: 높음 · 행위 테스트 1단계(계약 117)를 god에서 green으로

- **왜 다음인가:** 계약(ADR-0003)과 판정(행위 테스트·verify)이 준비됐다. 레이어드 분리의 출발점이다.
- **발생 가능한 문제 (이번 작업에서 관측한 신호):**
  - verify의 호가 이력 검사는 **사이즈 단위 직렬화**(ADR-0003 §3.3)를 전제한다. 사이즈 행을 잠그지 않고 입찰 행만 잠그는 구현은 동시성 테스트 뒤 verify에서 간헐적으로 떨어진다(반증 표본 `bad_loser_unserialized`·`bad_interleave_same_size`).
  - 금액 해석 차이: 생성기·verify의 1원 배분·적립 기준과 다르면 verify가 잡는다(이전 작업 실측: verify 1차 위반 347건 중 190건이 1원 배분).
  - 포인트 예약은 RESERVED 시점에 배분·remaining 차감(ADR-0002 §9.6) — 생성기와 중간 상태가 다르다.
  - 테스트 픽스처 제약: `CLOCK_START` < 약 2026-09-30이면 포인트 테스트 준비가 실패(run.sh는 기본값 사용).
- **방법론 선택지:**

| 방안 | 요지 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|----------|----------|
| A | 계약 조항 순서대로(입찰 → 체결 → 결제 → 배치) 한 클래스에 쌓기 | 테스트 단위 진행 | 후반 결제·배치에서 앞 설계를 갈아엎음 | 갓 클래스 원래 의도(절차를 한 곳에) |
| B | 결제·포인트 금액 계산을 먼저 완성(§8 표) 후 HTTP | 금액 실수 조기 발견 | HTTP·상태 전이와 따로 놀 수 있음 | 금액이 최대 위험일 때 |

- **권장 대처:** A. 매 단계 run.sh로 green 수를 기록하고, 동시성·배치 테스트 뒤 verify까지 통과시킨다.
- **착수 전 확인할 것:** 갓 클래스 경계(컨트롤러·엔티티·DTO는 밖 — ADR-0002 §8), JPA 엔티티 범위, 트랜잭션·잠금 방식.
