## 1. 목표·대상 (필수)

- **대상:** `clean-code-llm-experiment`, 브랜치 `feat/behavior-tests-stage1`(main `6be30b8` 기준. ADR-0003 합의 커밋 뒤 분기).
- **산출물:**
  1. `docs/adr/0003-http-api-stage1.md` 합의본(L0 — 이 작업의 기준소스).
  2. Gradle 모듈 `behavior-tests/`(Kotlin, JUnit 5): `BASE_URL`·`DB_URL`·`PG_URL`로 대상 앱을 가리켜 ADR-0003 1단계 계약을 검증하는 테스트. 같은 코드로 god·layered를 각각 돌린다.
  3. 가짜 PG(같은 모듈, JDK 내장 HTTP 서버 — ADR-0003 §6).
  4. 실행 스크립트 `tools/behavior/run.sh <god|layered>`: 1천 명 시드 컨테이너 → 가짜 PG → 앱 jar(env로 DB·PG 연결) 기동 → 테스트 → 정리. 결과는 JUnit 리포트.
  5. `build-image.sh`의 이미지 정리 규칙을 "같은 규모 태그의 이전 빌드만 지운다"로 변경, 1천 명 이미지 `1k-s42` 재빌드.
- **끝의 정의:** 테스트가 컴파일·실행되고, 아직 구현이 없는 두 앱에서 **계약 테스트가 전부 실패(red)** 하며 실패 이유가 "엔드포인트 없음(404)" 류로 일관된다. 가짜 PG와 DB 조회 도우미는 자체 테스트로 green.

## 2. 경계·불변식 (필수)

- 테스트는 ADR-0003·ADR-0002만 보고 쓴다. 앱의 내부 구조(클래스·패키지)에 의존하지 않는다 — HTTP와 DB 테이블만 접점.
- 같은 테스트 코드가 두 앱에 그대로 돈다(앱별 분기 없음).
- 테스트 간 독립: 테스트는 **직렬로** 실행한다. 각 테스트는 스스로 만든 사용자·상품·사이즈(직접 INSERT)만 쓰고 그 행만 단언한다. 배치 `processed`는 정확한 값을 단언하지 않는다(시드·다른 테스트 행도 처리됨 — ADR-0003 §7). 실행 순서에 의존하지 않는다.
- 시각: 시계는 앞으로만 간다(ADR-0003 §7). 테스트는 현재 시계를 읽고 그 뒤로 옮긴다 — 절대 시각을 가정하지 않는다.
- 오류 단언은 HTTP 상태와 `code`를 함께 본다(라우트 없는 404로 통과하는 그린 위장 방지).
- 금액 기대값은 ADR-0003 §8 표가 정본이다.
- 시드 이미지는 읽기 원본이다. 실행 컨테이너는 1회용(끝나면 삭제).

## 5. 검증 방법 (필수)

- `./gradlew :behavior-tests:test`(JDK 21)가 컴파일·실행된다.
- `run.sh god`·`run.sh layered`: 두 앱에서 계약 테스트가 모두 실패, 실패 원인 분포를 기록(그린 위장 방지 — 구현이 없는데 통과하는 테스트가 있으면 그 테스트가 계약을 검증하지 않는 것).
- 테스트 자체 검증: 가짜 PG·DB 도우미 자체 테스트 green. 금액 테스트의 기대값이 ADR-0003 §8 표와 일치하는지 리뷰에서 대조.
- 테스트 스위트 끝에 `verify.sql` 1회(ADR-0003 §11) — 구현 전에는 시드만 있으므로 통과해야 한다.
- 반증: 계약 테스트 몇 개를 골라, 일부러 기대를 깨는 최소 스텁(테스트 소스 밖 임시 서버)으로 실패를 확인 — 테스트가 실제로 응답·DB를 보는지.

## 6. stakes (필수)

- 판정: **높음** — 근거: 이 테스트가 두 구현과 이후 에이전트 과제의 정답 판정 계약(public contract)이다. 틀리면 이후 모든 측정이 오염된다.
- 리뷰: ADR-0003은 설계 문서 → 설계 선검증 + 듀얼 1패스. 테스트 코드는 실행물 → 듀얼 리뷰 루프(≤3). blind 테스트 워커: 이 작업 자체가 구현 없는 계약 테스트라 테스트 설계 워커가 구현 diff를 볼 수 없다 — 테스트 작성은 ADR만 받은 별도 Opus 워커가 하고, 메인은 판정·통합만 한다.

## 8. load-bearing 가정

1. 1천 명 시드 컨테이너 + 앱 jar + 가짜 PG를 한 스크립트로 띄우고 테스트를 돌리는 데 실행당 1분 안팎이면 충분하다.
2. ADR-0003 계약만으로 두 구현이 같은 DB 결과를 낼 만큼 결정적이다(같은 요청 → 같은 행·금액). 결정적이지 않은 값(id·pg_tx_id·시각 외)이 남으면 계약을 고친다.
