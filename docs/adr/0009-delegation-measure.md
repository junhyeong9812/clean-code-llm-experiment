# ADR-0009: 탐색 위임 측정 — Opus 메인이 탐색을 싼 모델 워커에 맡기면 성공을 잃지 않고 비용이 주는가

- 상태: **채택**(2026-11-03, 사용자 합의 — [제안] 값 그대로: 비열등 마진 −0.10, 탐색량 문턱 2배, R ≥12/14·R_D ≥5/6 칸, 게이트 7·8) · **[제안]** = 메인이 정한 수치·세부로, 채택 때 사용자가 확인했다.
- 앞 결정: [ADR-0005](0005-tasks-judging-runner.md)(러너·판정·무효 처리) · [ADR-0008](0008-search-cost-tasks.md)(과제 S1~S4·채택 수준·fce) · [3차 결론](../results/third-conclusion.md)(§3.3 사후 관찰)
- 근거 기록: `docs/plans/2026-11-03/delegation-measure/`(인터뷰·스모크·과제 후보 조사 DEL-W1·리뷰 ledger)
- **사후 선택 표시:** 이 질문은 3차 결론의 사후 관찰(캐시 읽기 75~93%, 찾기 1~3턴)과 사용자 가설에서 나왔다. 아래 기준은 파일럿 전에 고정하지만 질문의 선택은 앞 결과를 본 뒤다(§10의 1).
- **쓰임:** 결론은 claude-code-harness 워커 위임 규칙(core §5 "워커 위임 기본 Opus·high") 개정의 입력이다. 하네스 개정은 이 결론 뒤 별도 작업이다(보류 브랜치 `harness-search-findings`).

## 1. 맥락

- 하네스는 메인(Opus)이 인터뷰·결정·종합을 맡고, 대량 읽기·탐색은 워커에 맡긴다. 워커 기본 모델은 Opus다 — **하네스 현행 = Opus 메인 + Opus 워커 위임.**
- 사용자 가설(2026-11-02): 탐색·정리를 Haiku·Sonnet 워커에 맡기고 메인은 그 재료로 결정만 하면 토큰(비용)이 준다.
- 반대 방향의 힘: 워커도 시스템 프롬프트·브리핑을 새로 읽고 요약을 돌려준다(고정 비용), 약한 모델 요약은 놓치거나 지어낼 수 있다(성공 하락), 작은 탐색은 위임이 손해일 수 있다. 1~3차 결론의 과제는 찾기가 1~3턴이라 위임에 불리하다 — 탐색량이 큰 과제를 함께 쓴다(§4).

## 3. 위임 방식

### 3.1 장치 (러너 `--arm`, 커밋 `948e347`·`af01559`)

- `explore-*`: 격리 HOME의 `.claude/agents/explorer.md`에 서브에이전트를 정의한다 — 모델 = haiku·sonnet·opus 별칭, 본문 = "탐색 전담, 파일을 만들거나 고치지 않는다, 근거(경로·줄 번호)와 요지만 보고". frontmatter의 `tools: Bash, Read, Grep, Glob` 중 CLI 2.1.308에 실제로 있는 도구는 Bash·Read다(스모크 init — Grep·Glob 없음, 해 없음).
- `solo`: HOME settings의 금지 도구에 Agent·Task를 더한다. explorer 정의도 위임 규칙 접미도 없다. **내장 서브에이전트(Explore·general-purpose 등)는 `explore-*`에서는 막지 않는다** — 메인이 explorer 대신 내장을 고를 수 있어, 실행마다 `subagent_types`(호출 순서대로)를 기록하고 보고한다.
- `direct`(1~3차 결론의 종전 방식, 내장 서브에이전트 허용)는 이 ADR에서 쓰지 않는다.
- 작업 사본은 방식과 무관하게 같다. 단 explorer의 "고치지 않는다"는 지시일 뿐 막는 장치가 없다 — 하위 에이전트 안의 쓰기 **시도**(편집 도구 입력·Bash 쓰기 해석, 추정)를 `sub_edit_paths`로 따로 기록하고 분석에서 표시한다(판정은 사본 결과 그대로, 실제 변경은 diff).
- 별칭이 어떤 모델로 풀렸는지 `by_model`·`cost_by_model`로 실행마다 기록한다(스모크: opus → `claude-opus-5-5`, haiku → `claude-haiku-5-5`).
- **스모크(가정 1 실증, 2026-11-03, S1 layered explore-haiku):** 메인이 턴 2에 explorer를 1회 호출했고, 서브에이전트 Bash 11회가 모두 `claude-haiku-5-5`로 돌았다. 성공(회귀 463 통과). 읽은 줄 sub 1,015 / main 187(이 중 48은 explorer가 돌려준 요약). 에이전트 197초 + 판정 약 13.5분(행 기록까지 1,016초).

### 3.2 프롬프트 접미 (`explore-*`만)

> 탐색 규칙: 고칠 곳 찾기·여러 파일 읽기·호출처 조사 같은 넓은 탐색과 대량 읽기는 Agent 도구로 explorer 서브에이전트에게 맡기고, 그 결과(파일 경로·줄 번호·요지)를 받아라. 결정과 편집은 네가 직접 한다. 편집 전에 explorer 가 가리킨 핵심 1~2곳은 직접 확인하라. grep 한두 번으로 끝나는 작은 조회는 직접 해도 된다.

- 주 질문(모델 효과)은 세 `explore-*` 방식끼리 비교라 접미·정의가 같고 explorer 모델만 다르다. 보조 질문(위임 효과 = `explore-opus` ÷ `solo`)에는 접미·도구 차단 차이가 함께 섞인다 — "위임 규칙을 포함한 방식 전체의 효과"로 해석한다(§10의 3).
- 위임 여부는 메인이 정한다. 호출 0인 실행도 표본에 둔다(의도대로 분석).

## 5. 지표

### 5.1 주 지표: 실행 명목 총비용

- 값 = CLI 결과 이벤트의 `total_cost_usd`(runs.jsonl `cost_usd`) — 메인 + 서브에이전트. 실행마다 `cost_by_model` 합과 일치하는지 검사하고, 어긋난 실행은 '모름'(§7.3).
- 스모크 확인: 모델별 `costUSD`(`costBasis: list`)가 따로 오고 합이 총비용과 같다(Opus 0.21704460 + Haiku 0.01012519 = 0.22716978).
- "명목": 구독 사용이라 청구액이 아니다. 모델 간 상대 비용의 대리값이다.
- 실패 실행도 비용은 센다.

### 5.2 비와 요약

- 칸 = 과제 × 구조(14칸). 칸 비 r = median(방식 A의 3회 비용) ÷ median(방식 B의 3회 비용).
- **모델 효과:** A = `explore-haiku`·`explore-sonnet`, B = `explore-opus`. **위임 효과:** A = `explore-opus`, B = `solo`.
- 요약 R = 14칸 r의 기하평균. R_D = D1~D3 6칸, R_S = S1~S4 8칸.
- **95% 구간:** 칸마다 두 방식의 회차를 각각 독립으로 복원 추출(짝짓지 않음)해 r을 다시 계산하고 기하평균을 낸다. 2,000회, 시드 `20261103`, 백분위 구간. R_D·R_S도 같은 재표본에서.

### 5.4 판정 범위 (사용자 결정 2026-11-03)

- 판정 1회가 약 13.5분(회귀 463개)이라 동시 1로 168실행이면 약 47시간이다. 그래서 **본 실행은 public·hidden 단계만** 판정하고 success = 두 단계 통과(러너 `--stages public,hidden`, 행의 `partial_stages`).
- 파일럿은 전 단계 판정해 public·hidden 판정과 전 단계 판정이 갈린 수를 보고한다(본 실행 판정 축소의 근거·위협 — §10의 10).
- 1~3차 결론의 success(전 단계)와 정의가 다르다. 비교하지 않는다.

## 6. 성공 비열등

- d = 성공률(A) − 성공률(B), 42실행씩(D만 볼 때 18실행씩).
- 95% 구간: **Newcombe 하이브리드 점수 구간**(두 독립 비율 차, Wilson 점수 기반). 재표본 백분위는 성공이 모두 같으면 폭이 0이 되어 쓰지 않는다. 예: 42/42 대 42/42 → [−0.084, 0.084](비열등), 40/42 대 42/42 → [−0.158, 0.043](불확실), 18/18 대 18/18 → [−0.176, 0.176].
- **비열등:** 구간 하한 > −0.10. **열등:** 구간 상한 < −0.10. 그 밖은 "성공 불확실". 비열등은 42실행 전체로만 판정한다(D 18실행으로는 모두 성공해도 하한이 −0.10 아래라 판정이 서지 않는다).
- **칸 바닥:** B가 3회 중 2회 이상 성공한 칸에서 A가 0회면 비열등이어도 그 과제를 "막힘"으로 표시하고 첫 행(§7.2)을 적용하지 않는다.

## 7. 파일럿·게이트·결과별 할 일 (사전 등록 — 파일럿 실행 전)

  6. `solo`에서 D마다 성공 ≥ 1/2(두 구조 중).
  7. `solo` 실행에 Agent·Task 호출이 0이다(위임 차단이 CLI에서 실제로 먹힘 — `subagent_types` 빈 목록).
  8. 판정 갈림: 32실행 중 public·hidden 통과인데 전 단계 실패인 실행이 **1 이하**. 2 이상이면 본 실행 판정 축소를 쓰지 않고 사용자 결정(전 단계 판정 + 일정 재검토).
- 파일럿 실측 벽시계로 본 실행 일정을 다시 추정해 함께 보고한다.

### 7.2 결과별 할 일 — 모델 효과(주, 방식마다, 위에서부터 처음 맞는 행)

| 결과 | 하네스에서 할 일 |
|---|---|
| R < 0.8 · R 구간 상한 < 1.0 · 비열등 · 막힘 없음 | 탐색 워커 기본 모델을 그 모델로(둘 다 맞으면 R이 작은 쪽) |
| R_D < 0.8 · R_D 구간 상한 < 1.0 · 비열등(42실행) · D 막힘 없음 | "큰 탐색에만 그 모델 워커" 규칙(둘 다 맞으면 R_D가 작은 쪽) |

| 열등 | 그 모델로 바꾸지 않는다 — "성공 손해"로 기록(비용과 따로) |
| 그 밖 | "불확실" — 현행 유지, 사용자 결정 |

### 7.3 위임 효과(보조 — 하네스 위임 범위 문구의 입력)

- 같은 표를 `explore-opus` ÷ `solo`에 적용한다. 첫 행이면 "위임은 비용에도 이득", 둘째 행이면 "큰 탐색에서만 이득", 셋째 행이면 "위임은 비용 손해(컨텍스트 보호 등 다른 이유로만)", 넷째 행이면 "위임은 성공 손해"로 하네스 위임 범위 문구의 근거에 쓴다. 모델 선택에는 쓰지 않는다.

### 7.4 결측·재실행

- 무효는 재실행 2회까지(스케줄 `--passes 3`, 끝에 미완료 키 보고).
- **비교마다 공통 유효 칸만 쓴다:** 두 방식 모두 그 칸에 비용 값이 있는 유효 실행이 2회 이상인 칸. R은 공통 칸이 **12/14 이상**, R_D는 **5/6 이상**일 때만 계산하고, 미달이면 그 비교는 "판정 불가"(사용자 결정). 재표본은 칸마다 남은 회차 수 그대로 추출한다.
- 성공률 분모는 두 방식의 공통 칸의 유효 실행 수다.
- 비용 합 검사(러너 `cost_check`: `cost_by_model` 합과 `cost_usd` 차 ≤ 1e-6이면 ok)가 mismatch·missing인 실행은 비용 계산에서 빼고(성공에는 넣는다) 수를 보고한다.

## 8. 실행 순서·시간·로그인

- **순서(`experiment/runner/del_schedule.py`):** 반복마다 14칸 순서를 시드 `20261103`으로 섞고, 칸 안의 4방식 순서를 (반복 + 칸 번호)만큼 회전한다. 러너를 실행 하나씩 부른다(`--parallel 1 --timeout 1800 --min-mem-gb 12`, 본 실행 `--stages public,hidden`). valid 행이 있는 키는 건너뛰어 다시 부르면 무효·미실행만 돈다.
- **로그인(`experiment/runner/keepalive.py`):** 러너는 원본 로그인 파일 만료까지 실행 상한 + 10분이 남아야 시작한다(2,400초). 갱신은 호스트 claude 사용 때만 일어나므로, 실험 기간에 호스트에서 1분마다 남은 시간을 보고 문턱 아래면 `claude -p ok --model haiku`를 러너와 같은 잠금 안에서 1회 부른다. **실측(2026-11-03 01:08~01:17, 1분 간격 호스트 호출):** 만료까지 13.0~5.2분에서는 호출해도 갱신되지 않았고, 4.2분 남았을 때 갱신되어 새 유효 시간이 **479.9분(약 8시간)**이 됐다. 그래서 문턱 = **5분**(`--below-min 5`). 러너는 40분 미만 남으면 기다리므로 8시간마다 약 35분 대기(약 7%)가 생긴다. 대기 시간은 러너 로그로 남는다.
- **시간(추정):** 파일럿 32실행 × 약 17분(전 단계 판정) ≈ 9시간. 본 실행은 에이전트 3~5분 + public·hidden 판정(파일럿에서 실측) — 판정이 5분이면 168 × 약 10분 ≈ 28시간, 로그인 대기 별도. 파일럿 뒤 다시 추정해 사용자 확인.
- **비용:** 스모크 S1 explore-haiku $0.227. 상한 $100(본 실행) — 파일럿 게이트 4.

## 10. 타당성 위협

1. **사후 선택:** 질문은 3차 결론의 사후 관찰에서 나왔다.
2. **과제 표본:** 유형별 1개(D)·S1~S4는 작은 탐색. 결론은 "이 과제 7개에서"로 한정한다. D는 메인(Claude)이 골랐다.
3. **위임 효과의 혼입:** `solo`는 위임 규칙 문장이 없고 Agent 도구가 막혀 있다. 위임 효과(보조)는 방식 전체의 효과다. 주 질문(모델 효과)에는 해당 없음.
4. **내장 서브에이전트:** `explore-*`에서 메인이 explorer 대신 내장 Explore 등을 쓸 수 있다. 호출 종류를 보고한다.
5. **명목 비용:** 청구액이 아니다. 단가 표가 바뀌면 비가 바뀐다.
6. **캐시:** 캐시 쓰기·읽기는 실행 순서·직전 실행(같은 방식이면 시스템 프롬프트·에이전트 목록 공유)에 영향을 받는다(3차 결론 §3.3). 칸 안 방식 순서 회전으로 섞고, 캐시 쓰기 토큰을 공변량으로 보고한다.
7. **위임 미호출:** 지시해도 메인이 위임하지 않으면 방식 간 차이가 줄어든다. 호출 비율을 보고한다.
8. **별칭 해석:** 별칭이 실행 기간 중 다른 모델로 풀릴 수 있다 — `cost_by_model` 키로 확인.
9. **3회 반복:** 칸마다 3회라 중앙값이 불안정하다 — 구간으로 표시. 비열등 마진 −0.10은 [제안]이다. 42실행 Newcombe 구간은 성공률이 같아도 실패가 몇 건 섞이면 하한이 −0.10 근처라, "성공 불확실"이 자주 나올 수 있다(그때는 표의 넷째 행 밖 — "그 밖" 행).
10. **판정 축소:** 본 실행은 회귀를 판정하지 않는다. 회귀만 깨는 답안(explorer의 무관한 쓰기 포함)이 성공으로 잡힌다 — 파일럿의 갈림 수와 `sub_edit_paths`로 크기를 보고한다.
11. **메인 모델 하나:** Opus 메인만 잰다.
12. **탐색량 문턱:** 기준이 같은 파일럿의 S1~S4 `solo`라 같은 단위지만, 2배는 [제안]이다.
