# ADR-0001: 기본 세팅 — 두 서버(god·layered) + 도커 PostgreSQL

- 상태: 채택 (2026-10-13)
- 범위: 저장소 뼈대와 앱 기동까지. 도메인 설계(결제·입찰·구매·정산·포인트), 데이터 생성, 실험 설계는 다음 ADR에서 다룬다.

## 맥락

- [graph-nav-experiment](https://github.com/junhyeong9812/graph-nav-experiment)의 결론: 에이전트의 탐색 비용과 정답률은 미리 만든 지도보다 코드의 아키텍처(지엽성)와 네이밍이 정했다.
- 그 실험은 모든 변형이 같은 레이어 구조를 유지했다. 그래서 "레이어가 없으면 어떻게 되는가"는 재지 못했다.
- 이 저장소는 그 질문을 잰다. 사람에게 좋은 설계(캡슐화·지엽성·레이어·클린 코드)가 LLM 에이전트에게도 좋은가.

## 결정

### 1. 같은 동작, 두 구조

| 모듈 | 구조 | 포트 | DB |
|---|---|---|---|
| `god` | 갓 클래스: 결제 절차의 시작과 끝(절차·규칙·저장)을 클래스 1개, 파일 1개에 담는다 | 8081 | `ccle_god` |
| `layered` | `api · service · domain · infra` 계층 | 8082 | `ccle_layered` |

- 구현 순서: 갓 클래스(절차지향)를 먼저 만들고, 그것을 레이어드로 분리하면서 도메인을 끌어낸다. 같은 동작은 두 모듈이 공유하는 HTTP 수준 행위 테스트로 보장한다.
- 규모: 구현당 1만 줄 이상(앞 실험에서 8만 줄도 grep 3턴이었으므로 너무 작으면 구조 차이가 드러나지 않는다).

### 2. 런타임과 버전

| 항목 | 값 | 이유 |
|---|---|---|
| 언어·프레임워크 | Kotlin 2.2.20, Spring Boot 3.5.5 | 앞 실험(fream, Spring)과 같은 생태계. 레이어 구조가 자연스럽다 |
| JDK | 21 (toolchain) | |
| 빌드 | Gradle 8.14.4 (wrapper), Kotlin DSL, 멀티 모듈 | 두 모듈의 의존성·설정을 루트 `subprojects`에서 같게 강제 |
| 의존성 | web, data-jpa, actuator, jackson-kotlin, postgresql 42.7.7 | |

- 모두 로컬 Gradle 캐시에 있는 조합이다. 실험 때 에이전트 사본이 네트워크 없이(`--offline`) 빌드돼야 하기 때문이다.

### 3. 데이터베이스: 실제 PostgreSQL, 같은 PC의 도커

- `docker/compose.yml`: `postgres:17`, 포트는 `127.0.0.1:15432`에만 연다. 앱과 테스트는 호스트에서 루프백으로 붙는다. 네트워크 IO 변동을 줄이기 위해서다.
- 두 구현은 같은 컨테이너의 서로 다른 DB(`ccle_god`, `ccle_layered`)를 쓴다(`docker/init/01-databases.sql`).
- 접속 정보는 환경변수(`DB_URL`·`DB_USER`·`DB_PASSWORD`)로 바꿀 수 있다. 기본값(`ccle/ccle`)은 로컬 개발 전용이다.
- 스키마는 `ddl-auto: validate`다. 스키마는 앱이 만들지 않고, 다음 단계의 DDL로 정의한다.

### 4. 다음 단계에서 정할 것 (이 ADR 범위 밖)

- 도메인: 결제·입찰·구매·정산 + 포인트(결제 금액 기반 적립, 결제 시 사용). 절차·상태 전이·DB 설계
- 데이터: 실제 같은 합성 데이터(사용자 50만, 거래 약 500만). 원본은 CSV이고 시드 고정 생성기로 재현한다(CSV·덤프는 git 밖). 적재 후 행 수·합계·고아 행으로 검증한다.
- 실험 격리: 실행마다 컨테이너. 시드를 적재한 이미지를 한 번 만들고, 실행마다 그 이미지로 띄운다.
- 디스크: 러너가 실행 전 여유 공간을 검사한다(앞 실험의 디스크 사고 교훈).

## 검증 (2026-10-13)

- `docker compose -f docker/compose.yml up -d` → healthy, `ccle_god`·`ccle_layered` 생성 확인
- `./gradlew build --offline` 성공. 스모크 테스트 2개(모듈당 1개, `/actuator/health` = UP)가 도커 DB에 실제 접속해 통과했다.
- 두 jar 기동: 8081·8082 모두 `{"status":"UP","components":{"db":{"status":"UP"},…}}`

## 결과

- 두 서버가 같은 의존성·같은 DB 엔진으로 뜬다. 이후 차이는 코드 구조에서만 나도록 출발점을 맞췄다.
